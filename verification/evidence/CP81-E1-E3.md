Observed result
---------------

E1 is **not zero-diff**. The 2,130 shared cases yield 1,126 differences:
1,120 accept/reject differences and six canonical-output differences. All six
committed baselines are accepted by both sides with equal canonical hashes.
Cases cover every field present in the baselines, including nested fields,
types/nulls, requiredness, every declared literal, declared numeric/string/list
bounds, and invalid array literals. Schema and per-field coverage are included
in `corpus.json`. This is a schema-derived finite corpus, not exhaustive JSON
fuzzing or proof of equivalence.

| Class | Differences |
| --- | ---: |
| Gateway signed scan payload | 14 |
| Successful report | 656 |
| Terminal report | 156 |
| Probe receipt document | 190 |
| QuoteProbeRequest | 108 |
| Gateway runner registration | 2 |

Go `wire.ValidateScanReportBody` enforces the envelope and canonical decoded
JSON, but has no report/probe field schema validator. Python uses
`SuccessfulVerificationReport`, `TerminalVerificationReport`, `ProbeReceipt`
and `QuoteProbeRequest`. Missing/wrong-type report fields therefore yield many
Go accepts and Python rejects. The test deliberately does not copy Pydantic
constraints into a new Go validator: that would mask the missing receiving
validation boundary.

The 14 signed scan differences are Python accepting numeric timestamps (2),
float/bool `hard_inference_budget.model_request_count` (2), a source handle
that is an OpaqueId rather than Go's UUID (5), or an alternate platform key ID
(5). Platform key ID differences include admission context: Go binds the
payload to the fixed test signing key; a standalone Pydantic model does not.
They are reported separately from intrinsic type/constraint differences.
Registration differs on numeric `registered_at_utc` (2).

Six cases accepted by both sides have different canonical output bytes:
successful report `accepted_at_utc` and terminal report `completed_at_utc`
each with integer/float epoch timestamps (4), and QuoteProbeRequest
`owner_consent=1.0`, standalone and inside ProbeReceipt (2). Pydantic
normalizes these to a UTC datetime string or `true`; Go preserves the
canonical JSON numeric input. Exact IDs, verdicts, output SHA-256 and Python
validation errors are in `diff.json`, with the original input in `corpus.json`.
No divergence was fixed.

The signed scan model is `GatewayScanPayload`, the payload actually carried
by the committed S1791 Ed25519 signed envelope. `SignedScanSpec` is the legacy
RSA wrapper and does not match that vector; its schema digest is also recorded
as explicitly legacy. Go signs each mutated payload with the committed
test-only key and calls `VerifyScan` at the committed vector's timestamp.
Report/probe mutations use the production receiving envelope boundary.
Python canonical output uses the backend `canonical_json_bytes` over the
validated model's full JSON-mode dump. Schema hashes use UTF-8 sorted compact
JSON with `ensure_ascii=False`.
